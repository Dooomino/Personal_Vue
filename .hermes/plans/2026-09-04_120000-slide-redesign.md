# Slide System Redesign Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Clean up the slide canvas/theme system — reduce 3-layer split ownership to a single coherent flow, eliminate 12 identical components, fix fragile non-reactive Map.

**Architecture:** SlideReveal owns the canvas (renders it as sibling of motion.div, not inside). Slide components get canvas via simple provide/inject (one ref, not a Map). 12 identical slides collapse into 1 parameterized component. useSlideCanvas simplified.

**Tech Stack:** Vue 3, motion-v, gsap, THREE.js, TypeScript

---

## Current Problems

1. **Canvas ownership split across 3 layers**: PortfolioView (DOM), SlideReveal (visibility trigger), useSlideCanvas (behavior), slide component (THREE.js) — four places for one concept
2. **Non-reactive Map + inject**: `canvasMap` is a plain `Map`, `computed` won't re-evaluate. Works by accident (1s delay) but fragile
3. **12 identical slide components**: Only `variant` differs. Every one has identical inject/computed/useSlideCanvas boilerplate
4. **Duplicate promise creation**: `useSlideCanvas` creates `animationDone` in both the watch handler AND `drawAndFadeIn` — redundant
5. **SlideReveal 105 lines**: Mixed concerns — visibility detection, motion presets, key management, snap/unsnap events

## Proposed Architecture

```
SlideReveal (visibility + motion + canvas DOM + provide canvasRef)
  └─ slot: SlideContent (layout + theme colors)
       └─ slot: slide-specific content (THREE.js, etc.)

useSlideCanvas(animated, canvasRef) → { canvasRef, animationDone }

PortfolioView → renders SlideReveal per project (no canvas, no Map)
```

## Task 2: Simplify useSlideCanvas — remove duplicate promise

**Objective:** Single promise creation point, cleaner API.

**Files:**
- Modify: `src/composables/useSlideCanvas.ts`

**Before (current):**
- Watch handler creates promise (line 67-69)
- drawAndFadeIn ALSO creates promise (line 54-56) — overwrites the first one

**After:**
```ts
export function useSlideCanvas(
  animated: () => boolean | undefined,
  canvasRef: Ref<HTMLCanvasElement | null>
) {
  let resolveAnimation: (() => void) | null = null
  let animationDone: Promise<void> = Promise.resolve()
  let pendingTimer = 0

  function clearCanvas() { ... } // unchanged

  function drawAndFadeIn() {
    if (!animated() || !canvasRef.value) return
    const canvas = canvasRef.value
    const ctx = canvas.getContext('2d')
    if (!ctx) return
    // ... gradient drawing (unchanged) ...
    gsap.fromTo(canvas,
      { opacity: 0 },
      { opacity: 1, duration: 1, onComplete: resolveAnimation! }
    )
  }

  watch(animated, (v) => {
    clearTimeout(pendingTimer)
    if (v) {
      animationDone = new Promise<void>((resolve) => {
        resolveAnimation = resolve
      })
      pendingTimer = setTimeout(() => nextTick(drawAndFadeIn), 1000)
    } else {
      clearCanvas()
    }
  })

  return { canvasRef, get animationDone() { return animationDone } }
}
```

Key changes:
- `canvasRef` is now required (not optional) — always provided by SlideReveal
- Promise created only in watch handler (not in drawAndFadeIn)
- Removed the duplicate promise creation

      new THREE.MeshBasicMaterial({ color: 0x00ff00 })

    renderer.render(scene, camera)

## Risks

- **SlideReveal canvas positioning**: Canvas must be sibling of motion.div, not child. CSS `position: absolute` + wrapper div ensures this.
- **provide/inject timing**: SlideReveal provides ref during setup (before mount). Slide components inject during their setup. Since they're descendants, inject works. Canvas element is available when `drawAndFadeIn` runs (1s after mount).
- **DefaultSlide variant prop**: Must be passed through to SlideContent. Verify SlideContent accepts it.
